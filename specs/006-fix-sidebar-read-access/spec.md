# Feature Specification: 修复侧边栏源码导航线程异常

**Feature Branch**: `master`

**Created**: 2026-08-25

**Status**: Draft

**Input**: User description: "侧边栏双击源码节点时出现 Read access is allowed from inside read-action only 异常，全程自行修复"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 正常打开侧边栏端点源码 (Priority: P1)

开发人员在 MQ 侧边栏双击一个仍然有效的端点或关系节点后，IDE 应直接打开其真实源码位置，不显示内部错误，也不需要再次操作。

**Why this priority**: 双击源码是侧边栏的核心导航动作；当前异常直接阻断了用户完成主要任务。

**Independent Test**: 准备队列、交换机、绑定、生产者和消费者节点，分别双击可导航节点，验证每次都打开对应源码且错误日志不新增线程访问异常。

**Acceptance Scenarios**:

1. **Given** 侧边栏存在有效的普通 MQ 端点节点，**When** 用户双击该节点，**Then** IDE 一次打开该端点的真实源码位置且不报告内部错误。
2. **Given** 侧边栏存在有效的死信交换机、绑定或目标队列关系节点，**When** 用户双击该关系节点，**Then** IDE 一次打开该关系对应的真实源码位置且不报告内部错误。
3. **Given** 用户连续多次双击不同可导航节点，**When** 每次导航完成，**Then** 所有目标都与选中节点一致且不会累积线程访问异常。

---

### User Story 2 - 安全处理失效源码位置 (Priority: P2)

当侧边栏快照中的源码位置因文件修改、删除或项目关闭而失效时，用户双击节点不会打开错误文件，也不会触发 IDE 内部异常。

**Why this priority**: 源码快照可能在刷新前失效；安全降级可以避免异常干扰开发环境。

**Independent Test**: 构造源码删除、位置失效和项目已关闭场景，双击对应节点，验证不发生错误导航或内部异常。

**Acceptance Scenarios**:

1. **Given** 节点对应源码位置已失效，**When** 用户双击该节点，**Then** 系统停止本次导航且不打开其他源码、不报告内部错误。
2. **Given** 项目在用户双击前已进入关闭状态，**When** 导航事件到达，**Then** 系统忽略该事件且不报告内部错误。
3. **Given** 用户双击的是分类、模块或诊断节点，**When** 该节点没有源码目标，**Then** 系统保持当前界面且不报告内部错误。

### Edge Cases

- 节点在鼠标按下后、导航执行前失效。
- 同一源码同时出现在主节点和关系节点中。
- 用户快速连续双击多个节点。
- 目标可读取但已不可导航。
- 项目正在关闭或已经释放。
- 双击坐标落在空白区域或当前选中项之外。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在用户双击有效侧边栏端点时打开该端点的真实源码位置。
- **FR-002**: 系统 MUST 对普通端点、特殊队列、交换机、绑定和关系目标使用相同的安全导航行为。
- **FR-003**: 系统 MUST 保证双击导航全过程不会在不允许的上下文读取源码模型，从而避免 IDE 内部线程访问异常。
- **FR-004**: 系统 MUST 在导航前确认项目、源码位置和导航目标仍然有效且可导航。
- **FR-005**: 当任一导航条件不满足时，系统 MUST 立即停止本次导航，不得打开近似或错误源码。
- **FR-006**: 系统 MUST 以用户实际双击坐标确定目标，不得使用可能过期的旧选中项。
- **FR-007**: 有效目标的双击导航 MUST 在 1 秒内开始打开源码，不得阻塞界面或启动轮询、重试。
- **FR-008**: 本修复 MUST 保持侧边栏刷新、搜索、模块折叠、缓存、关系展示和其他导航入口的既有结果不变。
- **FR-009**: 本修复 MUST NOT 修改用户项目文件，MUST NOT 连接或查询任何消息服务。
- **FR-010**: 本修复 MUST 仅覆盖已由日志确认的侧边栏双击源码导航路径，不得顺带重构其他导航入口。

### Scope Boundaries

**In Scope**:

- 侧边栏树中具有源码目标的节点双击导航。
- 普通端点和死信/延迟队列关系节点。
- 源码位置失效、项目关闭和不可导航目标的安全降级。
- 导航线程安全、现有行为回归和兼容性验证。

**Out of Scope**:

- 行标图标导航、编辑器其他跳转入口或通用导航框架重构。
- 改变节点单击、键盘操作、搜索、刷新或模块折叠体验。
- 新增弹窗、提示、重试、线程、锁、缓存或后台任务。
- 任何用户源码写入或消息服务运行时访问。

### Key Entities

- **侧边栏节点**: 用户实际双击的树节点，可表示端点、关系目标、分类、模块或诊断信息。
- **源码目标**: 节点关联的真实源码位置，具有有效、失效、可导航或不可导航状态。
- **导航动作**: 从双击坐标解析节点、校验源码目标并打开对应位置的一次用户操作。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对普通端点、特殊队列、交换机、绑定和关系目标各执行至少 20 次有效双击，源码打开正确率为 100%，线程访问异常数量为 0。
- **SC-002**: 对源码删除、位置失效、不可导航和项目关闭场景各执行至少 10 次双击，错误源码打开数量为 0，IDE 内部异常数量为 0。
- **SC-003**: 有效目标从双击到开始打开源码的时间在全部自动化样例中严格小于 1 秒。
- **SC-004**: 现有侧边栏刷新、搜索、模块折叠、缓存、关系展示及普通导航测试结果变化数量为 0。
- **SC-005**: 最低支持版本和最新明确验证版本均判定插件兼容，新增弃用 API 使用数量为 0。
- **SC-006**: 验证期间用户项目文件改动数量为 0，消息服务连接尝试数量为 0。

## Assumptions

- IDE 日志中的完整调用栈准确指向侧边栏双击源码导航入口。
- 现有智能源码位置继续作为跨刷新保存的唯一源码引用，不增加第二套位置存储。
- 失效目标沿用当前静默停止行为，不新增用户提示。
- 行标导航未出现在本次异常调用栈中，因此保持现状并仅进行回归验证。
