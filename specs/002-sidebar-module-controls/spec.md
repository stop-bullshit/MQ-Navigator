# Feature Specification: 侧边栏模块浏览与刷新优化

**Feature Branch**: 未创建（未配置 `before_specify` 分支钩子）

**Created**: 2026-08-24

**Status**: Ready for Planning

**Input**: User description: "优化侧边栏的功能，参考 `<reference-project>` 的侧边栏功能，里面有刷新，还支持按照模块折叠、展开。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按模块浏览侧边栏内容 (Priority: P1)

开发人员打开 MQ Navigator 侧边栏时，可以先看到当前项目的模块列表，并按需独立展开或折叠某个模块，以减少无关内容占用空间，快速聚焦正在排查的模块。

**Why this priority**: 多模块项目中的端点数量较多，模块级折叠与展开直接决定侧边栏是否可读，是本次优化最核心的用户价值。

**Independent Test**: 在包含多个模块且每个模块都有 RabbitMQ 端点的项目中打开侧边栏，分别展开、折叠不同模块，验证每个模块都能独立控制且仅显示其自身内容。

**Acceptance Scenarios**:

1. **Given** 当前项目包含多个有 RabbitMQ 端点的模块，**When** 用户打开侧边栏，**Then** 系统按模块展示分组，并在每个模块名称旁显示该模块当前可见端点数量。
2. **Given** 某个模块处于折叠状态，**When** 用户展开该模块，**Then** 系统显示该模块下现有的 Consumers、Producers 和 Topology 分类及其内容，不改变其他模块的展开状态。
3. **Given** 某个模块处于展开状态，**When** 用户折叠该模块，**Then** 系统隐藏该模块下的全部内容，但保留模块名称和数量，不改变其他模块的展开状态。
4. **Given** 侧边栏首次展示且没有可恢复的本次会话状态，**When** 模块列表加载完成，**Then** 根分组保持可见，各模块默认折叠，用户可以自行展开目标模块。

---

### User Story 2 - 在侧边栏主动刷新项目端点 (Priority: P2)

开发人员修改消息端点后，可以直接在侧边栏使用明确可见的刷新入口重新扫描当前项目，并在原位置查看最新模块、分类、数量和端点结果，无需进入其他菜单或重启 IDE。

**Why this priority**: 刷新能够解决用户对结果是否过期的疑问，并让侧边栏形成完整的自助更新流程，但模块浏览能力可以独立提供价值。

**Independent Test**: 打开侧边栏后新增、修改和删除 RabbitMQ 端点，分别点击侧边栏刷新入口，验证刷新后的树内容与当前可分析源码一致。

**Acceptance Scenarios**:

1. **Given** 侧边栏已经打开，**When** 用户查看侧边栏工具栏，**Then** 可以直接识别并使用刷新入口，无需打开其他菜单。
2. **Given** 用户新增、修改或删除了 RabbitMQ 端点，且项目当前可分析，**When** 用户点击刷新，**Then** 侧边栏更新模块、分类、数量和端点内容，结果与当前源码一致。
3. **Given** 刷新前有模块处于展开或折叠状态，**When** 刷新完成且该模块仍存在，**Then** 该模块保持刷新前的展开或折叠状态。
4. **Given** 刷新后出现新模块或原模块被删除，**When** 新结果展示，**Then** 新模块默认折叠，已删除模块不再显示，其他未变化模块的状态不受影响。
5. **Given** 用户在短时间内多次点击刷新，**When** 所有刷新操作结束，**Then** 最终展示不得回退到较早的项目结果。

---

### User Story 3 - 在筛选与搜索后保持浏览上下文 (Priority: P3)

开发人员使用现有文本搜索或端点类型筛选时，可以立即看到匹配模块中的结果；清除条件后，侧边栏恢复用户此前的模块展开状态，避免每次筛选都重新整理浏览位置。

**Why this priority**: 状态连续性能够避免模块折叠能力被搜索、筛选或树重建抵消，但不影响前两个故事独立交付。

**Independent Test**: 预先展开部分模块并折叠其他模块，执行文本搜索和类型筛选后清除条件，验证匹配结果可见且原模块状态得到恢复。

**Acceptance Scenarios**:

1. **Given** 匹配端点位于一个折叠模块中，**When** 用户输入搜索条件，**Then** 系统临时展示包含匹配结果的模块内容，使用户无需先手动展开模块即可看到结果。
2. **Given** 用户在搜索或筛选前已设置不同模块的展开状态，**When** 用户清除全部搜索和筛选条件，**Then** 系统恢复这些仍存在模块原有的展开或折叠状态。
3. **Given** 搜索或筛选没有匹配任何端点，**When** 结果更新，**Then** 系统明确显示当前条件下无结果，并保留用户清除条件后可恢复的模块状态。
4. **Given** 用户双击搜索、筛选或普通浏览结果中的端点，**When** 该源码位置仍有效，**Then** 系统继续打开正确源码位置，模块折叠优化不改变现有导航行为。

---

### Edge Cases

- 当前项目没有可识别的 RabbitMQ 端点时，侧边栏显示清晰的空状态，刷新入口仍可使用。
- 端点缺少明确模块名称时，继续归入现有的项目级分组，并允许按普通模块相同方式折叠和展开。
- 项目正在索引或暂时不可分析时，刷新不得清空已有可用结果；系统应说明暂时无法完成刷新，并在项目可分析后允许用户再次刷新。
- 某个模块在刷新过程中发生重命名时，旧模块视为删除，新模块视为新增并默认折叠。
- 搜索条件匹配多个模块时，所有包含匹配结果的模块均临时展示匹配内容，不展示无匹配模块的子内容。
- 刷新结果为空、部分端点无法解析或个别源码位置失效时，不得阻止其他有效模块和端点继续展示与导航。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 侧边栏 MUST 在现有 RabbitMQ 根分组下按当前项目模块组织端点。
- **FR-002**: 每个模块分组 MUST 展示模块名称和当前筛选条件下的端点数量。
- **FR-003**: 用户 MUST 能够独立展开或折叠任一模块，且操作一个模块不得改变其他模块的状态。
- **FR-004**: 在没有本次会话状态可恢复时，根分组 MUST 保持可见，各模块 MUST 默认折叠。
- **FR-005**: 展开模块后 MUST 继续展示该模块现有的 Consumers、Producers 和 Topology 分类；本功能不得改变这些分类的业务含义。
- **FR-006**: 侧边栏 MUST 提供始终可直接识别和操作的刷新入口。
- **FR-007**: 用户触发刷新后，系统 MUST 重新获取当前项目的 RabbitMQ 端点结果，并更新模块、分类、数量和端点内容。
- **FR-008**: 刷新成功后，仍存在且名称未变化的模块 MUST 保持刷新前的展开或折叠状态。
- **FR-009**: 刷新后首次出现的模块 MUST 默认折叠；不再存在的模块 MUST 从侧边栏移除。
- **FR-010**: 连续刷新时，系统 MUST 保证最终侧边栏展示不被较早的刷新结果覆盖。
- **FR-011**: 项目暂时不可分析或刷新失败时，系统 MUST 保留刷新前的可用内容，并向用户提供明确反馈，而不是展示为成功的空结果。
- **FR-012**: 文本搜索或端点类型筛选生效时，包含匹配结果的模块 MUST 临时展示匹配内容，用户无需额外手动展开。
- **FR-013**: 用户清除搜索和筛选条件后，系统 MUST 恢复仍存在模块在筛选前的展开或折叠状态。
- **FR-014**: 模块折叠、展开和刷新 MUST 保持现有端点双击导航、文本搜索、端点类型筛选和动态端点提示行为可用。
- **FR-015**: 模块折叠、展开、搜索和刷新 MUST 仅影响侧边栏展示，不得修改用户项目源码、配置、构建文件或连接真实消息服务。

### Scope Boundaries

**In Scope**:

- MQ Navigator 现有 RabbitMQ 项目级侧边栏的模块分组展示。
- 单个模块的独立折叠与展开，以及模块数量展示。
- 侧边栏内的手动刷新入口和刷新后的结果替换。
- 刷新、搜索和筛选期间的模块展开状态连续性。
- 无结果、项目暂时不可分析、部分端点失效和连续刷新时的用户反馈与安全降级。
- 现有搜索、类型筛选和双击源码导航在新交互下的兼容性。

**Out of Scope**:

- 为 Kafka 或 RocketMQ 新增项目级侧边栏。
- 新增独立的“全部展开”或“全部折叠”批量命令。
- 在 IDE 重启后永久保存模块展开状态。
- 改变消息端点扫描范围、消息匹配规则、动态值解析规则或源码导航目标。
- 连接 RabbitMQ 或其他消息服务查询运行时拓扑、状态或消息数据。
- 修改 `<reference-project>` 参考项目或依赖其源码运行本功能。

### Key Entities

- **模块分组**: 代表当前项目中一个包含可见 RabbitMQ 端点的模块；具有模块名称、可见端点数量和当前展开状态。
- **侧边栏结果快照**: 用户当前看到的模块、分类、端点和数量集合；刷新成功后被最新可分析项目结果替换。
- **模块展开状态**: 记录本次侧边栏会话中各模块是展开还是折叠；用于刷新和筛选结束后恢复浏览上下文。
- **刷新结果**: 一次用户主动刷新产生的成功、暂不可用或失败结果；成功结果包含最新侧边栏快照，非成功结果不得破坏已有可用内容。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在包含至少 10 个模块的验收项目中，用户对任一模块完成展开或折叠只需一次直接操作，且 100% 的操作不改变其他模块状态。
- **SC-002**: 在项目可分析的前提下，新增、修改或删除端点后执行刷新，100% 的验收样例最终展示与当前源码一致，且 95% 的刷新在 3 秒内呈现最新结果。
- **SC-003**: 在包含 50 个模块和 2,000 个 RabbitMQ 端点的验收项目中，至少 90% 的首次试用开发人员能在 5 秒内展开指定模块并定位到指定分类。
- **SC-004**: 对仍存在且名称未变化的模块，刷新完成或清除搜索筛选后，展开状态恢复准确率达到 100%；新模块默认折叠准确率达到 100%。
- **SC-005**: 在普通浏览、搜索结果和类型筛选结果中，现有有效端点的双击源码导航成功率保持 100%，错误跳转数量为 0。
- **SC-006**: 刷新失败、项目暂时不可分析或无匹配结果的全部验收场景均提供可理解反馈，且已有可用侧边栏内容丢失次数为 0。
- **SC-007**: 完整验收期间，用户项目源码、配置和构建文件的非用户改动数量为 0，对真实消息服务的连接次数为 0。

## Assumptions

- 本次优化对象是当前已有的 RabbitMQ 侧边栏，不扩展新的消息系统侧边栏。
- `<reference-project>` 仅作为刷新入口、模块树和折叠浏览方式的只读交互参考，不要求复制其全部功能或内部设计。
- 模块名称在同一次项目会话中可用于识别同一模块；模块重命名按删除旧模块并新增新模块处理。
- 首次加载或新模块没有历史状态时默认折叠，以减少多模块项目打开侧边栏时的信息密度。
- 搜索和类型筛选期间允许临时展开匹配模块；临时状态不会覆盖用户原有的模块展开选择。
- 现有 Consumers、Producers、Topology 分类、端点数量口径、搜索范围和双击导航行为保持不变。
- 刷新只重新获取当前打开项目中可静态分析的结果，不读取运行时 broker 数据。
