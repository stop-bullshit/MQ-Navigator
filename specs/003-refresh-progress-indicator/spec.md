# Feature Specification: RabbitMQ 刷新进度提示

**Feature Branch**: 未创建（未配置 `before_specify` 分支钩子）

**Created**: 2026-08-24

**Status**: Ready for Planning

**Input**: User description: "`正在刷新 RabbitMQ 端点` 是不是可以加上一个进度条。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 直观看到刷新仍在进行 (Priority: P1)

开发人员点击侧边栏刷新后，在“正在刷新 RabbitMQ 端点”文字旁看到持续活动的进度提示，从而明确系统正在处理，而不是误以为刷新按钮无效或界面卡住。

**Why this priority**: 进度反馈是本功能的直接用户价值；仅交付该故事就能解决刷新期间缺少视觉反馈的问题。

**Independent Test**: 在可控制刷新完成时机的验收项目中触发一次持续至少 500 毫秒的刷新，验证刷新期间进度提示可见且持续活动，刷新结束后自动消失。

**Acceptance Scenarios**:

1. **Given** 侧边栏已展示 RabbitMQ 端点，**When** 用户触发一次持续中的刷新，**Then** 系统同时显示“正在刷新 RabbitMQ 端点”文字和活动中的进度提示。
2. **Given** 刷新仍未结束，**When** 用户继续查看侧边栏，**Then** 进度提示保持可见和活动，不显示无法证明的完成百分比或剩余时间。
3. **Given** 最新刷新成功完成，**When** 新结果已经展示，**Then** 进度提示停止并消失，侧边栏恢复对应的非刷新状态反馈。

---

### User Story 2 - 在各种刷新结果下正确结束提示 (Priority: P2)

开发人员在连续刷新、索引等待、空结果或刷新失败时，始终能从进度提示和状态文字区分“正在扫描”“等待索引”和“刷新已结束”，并继续使用刷新前的可用侧边栏内容。

**Why this priority**: 错误结束或提前结束的进度提示会产生比没有提示更强的误导，因此必须覆盖现有刷新结果和连续请求边界。

**Independent Test**: 分别模拟成功、合法空结果、索引等待、失败和两个请求反向完成，验证进度提示只跟随最新请求，在扫描阶段活动，在等待索引和最终状态下隐藏。

**Acceptance Scenarios**:

1. **Given** 用户连续触发两次刷新，**When** 较早请求先结束但最新请求仍在处理，**Then** 进度提示继续显示，不得被较早结果提前关闭。
2. **Given** 用户连续触发两次刷新，**When** 最新请求已经结束而较早请求随后返回，**Then** 较早结果不得重新显示进度提示或改变最新状态。
3. **Given** 最新刷新正在等待项目索引，**When** 系统显示“等待项目索引完成”，**Then** 进度提示保持隐藏，已有可用侧边栏内容继续保留。
4. **Given** 最新刷新失败，**When** 系统显示失败反馈，**Then** 进度提示结束，已有可用侧边栏内容不因进度展示而丢失。
5. **Given** 最新刷新得到合法空结果，**When** 空状态展示，**Then** 进度提示结束，空结果不得继续显示为刷新中。

---

### User Story 3 - 刷新期间继续浏览已有结果 (Priority: P3)

开发人员等待刷新时，可以继续查看已有模块、搜索和筛选结果；进度提示不会遮挡侧边栏操作，也不会反复改变布局。

**Why this priority**: 该故事保证新增反馈不破坏上一项侧边栏优化，但不影响进度提示作为独立功能先行交付。

**Independent Test**: 在刷新保持进行的条件下操作模块折叠、文本搜索和类型筛选，验证控件可用、已有结果可浏览，且进度提示区域稳定。

**Acceptance Scenarios**:

1. **Given** 侧边栏已有可用结果且刷新正在进行，**When** 用户展开或折叠模块，**Then** 操作仍可完成，进度提示不遮挡树内容或刷新入口。
2. **Given** 刷新正在进行，**When** 用户使用现有文本搜索或类型筛选，**Then** 现有结果仍可按原规则浏览，进度提示不会把刷新中的状态误写成筛选结果状态。
3. **Given** 进度提示出现或消失，**When** 用户观察侧边栏布局，**Then** 主要内容区域不发生反复跳动，现有模块状态不因进度提示改变。

---

### Edge Cases

- 刷新在很短时间内完成时，进度提示可以短暂出现或来不及被用户感知，但不得在刷新结束后残留。
- 两次或多次刷新反向完成时，只有最新请求可以决定进度提示和最终状态。
- 项目进入索引等待时，进度提示保持隐藏；项目关闭后不得继续更新已释放的侧边栏。
- 刷新失败或返回合法空结果时，进度提示必须与对应反馈同步结束，不得让用户同时看到互相冲突的状态。
- 刷新期间用户改变模块展开状态、搜索文本或类型筛选时，进度提示不得覆盖这些用户操作。
- 侧边栏空间较窄时，进度提示不得遮挡刷新入口或关键状态文字。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 只要侧边栏处于“正在刷新 RabbitMQ 端点”状态，系统 MUST 同时展示可识别的活动进度提示。
- **FR-002**: 在无法可靠计算完整工作量时，进度提示 MUST 表达“正在进行”，不得展示推测的完成百分比、剩余时间或阶段数量。
- **FR-003**: 最新刷新处于“正在刷新 RabbitMQ 端点”扫描阶段时，进度提示 MUST 保持活动状态。
- **FR-004**: 最新刷新进入成功、合法空结果或失败状态后，进度提示 MUST 停止并消失；进入“等待项目索引完成”状态时，进度提示 MUST 保持隐藏。
- **FR-005**: 系统 MUST 保留现有刷新状态文字；进度提示不得替代成功、空结果、无匹配、索引等待或失败反馈。
- **FR-006**: 连续刷新时，较早请求的完成或失败 MUST NOT 提前结束最新请求的进度提示，也不得重新激活已结束的提示。
- **FR-007**: 展示和结束进度提示 MUST NOT 清空、替换或重建已有侧边栏结果；结果变化仍只由最新有效刷新结果决定。
- **FR-008**: 刷新期间用户 MUST 仍能浏览已有结果，并使用现有模块折叠、展开、文本搜索和类型筛选功能。
- **FR-009**: 进度提示 MUST NOT 遮挡刷新入口、关键状态文字或主要树内容，也不得造成主要内容区域反复跳动。
- **FR-010**: 本功能 MUST 保持现有端点数量、模块状态恢复、动态端点提示和双击源码导航行为不变。
- **FR-011**: 本功能 MUST 仅提供侧边栏视觉反馈，不得修改用户项目文件或连接 RabbitMQ 及其他消息服务。

### Scope Boundaries

**In Scope**:

- 现有 RabbitMQ 侧边栏“正在刷新 RabbitMQ 端点”状态的活动进度提示。
- 进度提示在成功、空结果、索引等待、失败和连续刷新下的生命周期。
- 刷新期间已有侧边栏内容和现有交互的可用性。
- 进度提示出现、活动和消失时的布局稳定性与状态一致性。

**Out of Scope**:

- 展示具体完成百分比、剩余秒数、已扫描文件数或刷新阶段明细。
- 新增取消按钮、暂停按钮、自动刷新、后台任务历史或完成通知。
- 处理独立于项目关闭之外的刷新取消操作。
- 改变 RabbitMQ 端点扫描、匹配、缓存、刷新顺序或结果应用规则。
- 为 Kafka、RocketMQ 或其他工具窗口新增刷新进度提示。
- 修改现有状态文案、搜索范围、类型筛选规则、模块折叠规则或导航目标。
- 连接真实消息服务获取运行时进度或拓扑数据。

### Key Entities

- **刷新进度状态**: 表示最新一次 RabbitMQ 侧边栏刷新是否仍在处理中；只有“进行中”和“已结束”两类用户可见状态，不包含百分比。
- **最新刷新请求**: 当前有权决定进度提示和最终状态的用户刷新操作；较早请求的结果不得覆盖它。
- **刷新结果状态**: 最新刷新扫描前的索引等待状态，以及扫描结束后的成功、合法空结果或失败结果；决定进度提示何时活动、隐藏以及显示何种现有反馈。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 5 次预热后，对至少 20 次持续至少 500 毫秒的受控刷新采样，活动进度提示显示延迟的第 95 百分位不超过 300 毫秒。
- **SC-002**: 在成功、合法空结果和失败三类结果各至少 5 次、索引等待至少 5 次的验收样例中，对应状态文字出现时进度提示状态正确率为 100%，最终状态的活动提示残留次数为 0。
- **SC-003**: 在至少 10 组连续刷新且请求反向完成的验收样例中，进度提示被较早请求提前结束或重新激活的次数为 0。
- **SC-004**: 刷新期间执行模块折叠、展开、文本搜索和类型筛选的全部验收样例均可正常完成，已有可用内容因进度提示丢失的次数为 0。
- **SC-005**: 至少 9/10 名首次使用者无需说明即可在 1 秒内判断 RabbitMQ 端点刷新仍在进行。
- **SC-006**: 完整验收期间，用户项目文件非用户改动数量为 0，对真实消息服务的连接次数为 0。

## Assumptions

- 当前 RabbitMQ 端点扫描没有稳定、准确的总工作量，因此默认采用不显示百分比的活动进度提示。
- 进度提示与现有“正在刷新 RabbitMQ 端点”文字同时出现，文字继续承担可读状态说明。
- “等待项目索引完成”表示 endpoint 扫描尚未开始，此时只显示等待文字，不显示进度条。
- 任何进入现有“正在刷新 RabbitMQ 端点”状态的刷新流程都适用本功能，不仅限于某一种刷新入口。
- 快速完成的刷新不要求用户一定能看到完整动画，但刷新结束后不得留下活动提示。
- 本功能复用现有最新请求优先、失败保留旧内容和项目只读边界，不改变刷新结果本身。
